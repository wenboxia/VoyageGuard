# VoyageGuard · 出行气象决策 Agent

**订了船票机票，遇上大风天，到底还走不走？**

将实时气象数据与官方发布的预警标准、禁限航规定逐项比对，判断出行当天是否越过某条官方判定线，并为每一项结论注明出处；
必需证据不足时输出「证据不足」，不给出风险等级。覆盖航空与船舶两类场景，支持中英双语。

  <tr><td width="64"><b>问&#8288;题</b></td><td>航司与船务 App 只通报已取消的班次，天气 App 只提供数值，官方公告发布滞后且分散；缺少将气象数值对照官方判定线的一层</td></tr>
  <tr><td width="64"><b>做&#8288;法</b></td><td>代码预取必需证据 → 模型给出解释与建议 → 规则引擎在模型循环之外做最终判定</td></tr>

## 使用方式

访问 **[voyageguard-two.vercel.app](https://voyageguard-two.vercel.app)**，无需登录：

|        | 步骤 | 说明 |
| ------ | --- | --- |
| **01** | 填写出发地与目的地 | 也可使用「快速体验」中的三个预设 |
| **02** | 选择日期与交通方式 | 可选今天起 3 天。选择船只时需指定船型，未指定则按小船的严格标准判定 |
| **03** | 查看结论 | 风险等级与触发的官方判定线（出处可点击）；展开「Agent 执行轨迹」可查看每一步的真实调用 |

示例输入：

| 输入 | 预期结果 |
|---|---|
| `烟台 → 大连` 船只 | 证据中包含**航线中点**；仅采样港口会漏判真实停航 |
| `北京 → 西安` **船只** | **证据不足**，且**不显示出行建议** |
| `上海 → 南极` 飞机 | 弃权，而非「低风险，建议出行」 |
| 展开 **Agent 执行轨迹** | 真实的工具名、参数与耗时；确定性预取与模型自主调用分别标注 |

界面右上角提供中英文切换（仅在填表页显示）与本仓库链接。

## 问题与场景

大风天气下是否按原计划出行，目前需要用户自行汇总多个渠道的信息，而每个渠道只覆盖问题的一部分：

| 渠道 | 局限 |
|---|---|
| 航司 / 船务 App | 只通报**已经**取消的班次，无法支持提前一天的判断 |
| 天气 App | 提供「风速 14 m/s」这类数值，但不说明其**含义** |
| 官方公告 | 权威，但发布滞后，且分散在各地海事局与航司渠道 |

**缺少的是中间一层：将气象数值对照官方判定线。**
该场景属于安全相关决策，漏报与误报的代价不对称：应提醒而未提醒的后果，远重于多提醒一次。

## 需求分析与产品边界

设计之初需要明确：**本产品是否有依据回答「这班船会不会停航」？**

结论是否定的。[交通运输部对人大建议的答复函](https://xxgk.mot.gov.cn/jigou/haishi/202006/t20200630_3319352.html)
指出：船舶抗风能力按**风压**计算，与蒲福风级**不存在对应关系**，因此官方**不在船舶证书上标注抗风等级**。
实际决策链为：各船自身的稳性限制 → 船公司判断 → 海事部门可下达指令 → 地方另有统一规定。

**因此，本产品只陈述一件事：出行当天是否越过了某条官方发布的预警或禁限航判定线。** 是否停航由承运人与主管部门决定。

这一定位直接决定了三项设计：

| 定位 | 对应设计 |
|---|---|
| 只陈述越线，不预测停航 | 输出为**带出处的触发项列表**，每条标明属于法规还是预警标准；中 / 高风险结论强制附「以官方通知为准」 |
| 是否越线是事实判断，而非意见 | **判定权归规则引擎**，不归模型 |
| 缺乏依据时不给结论 | 增加第四种结论 **`UNKNOWN`（证据不足）**，该判定同样不由模型做出 |

第三项是一种独立的输出，而非附在结论后的免责声明：

## 架构

本项目的核心产品决策，是划分哪些环节交给模型、哪些环节由确定性代码完成。每个请求依次经过三段处理：

<p align="center">
  <img src="docs/images/architecture.png" alt="架构：确定性证据管线 → 模型 ReAct 循环 → 规则引擎 verifier；证据不足时跳过模型" width="880">
</p>

| 环节 | 执行方 | 判定权 |
|---|---|---|
| 安全判定所需的证据 | `evidence.py` 确定性预取 | 不经模型 |
| 解释、建议与多因素权衡 | 模型 | 模型自由裁量 |
| 最终风险等级与触发项列表 | `rules.py` 规则引擎 | 不经模型 |

各段的职责边界由代码结构保证，不依赖 prompt 约束。详细设计见 [docs/architecture.md](docs/architecture.md)。

## Agent 设计

下表列出系统采用的机制及其代码位置。

| 机制 | 实现 | 位置 |
|---|---|---|
| ReAct 循环 | 模型可多轮调用工具补充证据，最多 5 轮 | `agent.run_agent` |
| 工具调用 | OpenAI 兼容的 function calling；2 个补充证据工具：预警搜索、第三地天气 | `agent.TOOLS` |
| 证据预取与结构化注入 | 安全判定所需的数据在调用模型**之前**取得，以结构化 JSON 注入 user message | `evidence.build_evidence` → `agent.build_user_message` |
| 循环外 verifier | 规则引擎位于模型循环**之外**，持有最终判定权 | `rules.evaluate` |
| 弃权（Abstention） | 第四种结论 `UNKNOWN`；是否弃权由规则引擎依据证据充分性决定，不由模型决定 | `rules.evaluate` |
| 执行轨迹与溯源 | 每个数值附 `source` 与 `fetched_at`；前端展示真实执行轨迹，区分确定性步骤与模型自主调用 | `evidence.TraceStep` |
| 失败降级 | 模型调用失败、超时或输出无法解析时，由规则引擎独立给出结论（`rule_only`） | `agent` + `rules` |
| 多模型选型 | 4 家模型通过环境变量切换，依据 L1 横评结果选定生产模型 | `providers.py` |

**未采用的机制**

| 机制 | 原因 |
|---|---|
| Memory / 上下文压缩 | 单次决策查询，没有长程任务，也没有需要跨轮次保留的状态 |
| Multi-agent | 任务为「获取两三处数据 → 对照阈值 → 给出结论」，拆分只会增加协调开销与失败点 |
| RAG | 判据全文仅数百字，直接写入 system prompt 即可；在这一规模上向量检索没有收益 |
| MCP / Skills | 仅 2 个工具且均在进程内，没有跨进程或第三方工具的接入需求 |
| 多步规划 | 流程固定为三段，不需要模型自行规划执行路径 |
| 微调 / RL | 判据为硬阈值，已由规则引擎实现，无需模型学习 |

## 关键设计决策

| 决策 | 依据 |
|---|---|
| **必需证据不交由模型获取** | 模型的弃权能力不可靠：本项目实测 24 次应弃权的机会中，模型错过 21 次 |
| **判定权归规则引擎** | 是否越线属于事实判断：越线而模型判低时强制升级，模型判高而指标不支持时降级 |
| **拦截前提不成立的查询** | 漏收一个机场只会导致弃权，放行一个不存在的航点则会给出「建议出行」，两类错误代价不对称 |
| **覆盖率本身是产品质量** | 优先使用官方数据，无法获取时回落并标明数据来源，而不是拒绝回答 |

<details>
<summary><b>展开各项决策的依据</b></summary>

<br>

**1. 必需证据不交由模型获取。** 模型可以自行调用工具，但风速、能见度、浪高等必需数据在调用模型之前已由代码取得。
依据是 AgentAbstain（[arXiv 2607.10059](https://arxiv.org/abs/2607.10059)）：最强模型在成对弃权任务上的准确率仅为 **59.5%**，
且弃权能力与通用任务能力基本无关，更换更强的模型无法解决。该结论已在本项目的评测中[复现](docs/evaluation.md#弃权是模型最不可靠的能力)。

**2. 判定权归规则引擎。** 规则引擎位于模型循环之外，按优先级执行三项检查：证据不足时直接输出 `UNKNOWN`；
越过硬性判定线而模型判低时强制升级；模型判为 HIGH 而结构化指标不支持时降级。
实际走了哪条路径，通过 `decision_source` 字段透出。

**3. 拦截前提不成立的查询。** 比等级判错更危险的，是在一个不成立的前提上给出确定的结论。
航空侧设有机场清单：判据只需要风速与能见度，而任何地名都能查到这两项，若无清单校验，「上海 → 南极」会得到「低风险，建议出行」。
地名解析设有两道校验：Geocoding 为模糊匹配，查询 `Xian` 返回 `Xián(西班牙) / Xianning / 咸阳 / 珠海市`，其中并无西安，
因此候选地名必须先与输入一致，再经海域回验。

**4. 覆盖率本身是产品质量。** 38 个机场发布官方 METAR/TAF，其余机场没有。本产品不采取「无官方数据即拒绝回答」的策略：
航空判据中只有能见度一项确实需要跑道观测，大风预警本身针对区域发布，城市地面风正是其输入。
因此数据源分级使用：官方数据优先，无法获取时回落，并在结果中标明本次使用的数据来源。

</details>

## 评测

评测分为四层，分别隔离不同的误差来源：

| 层 | 测试对象 | 隔离的因素 | 成本 |
|---|---|---|---|
| **L1 推理层** | 给定数据下模型的判断质量（39 条用例 × 4 家模型） | 网络、数据源、真实世界波动 | 消耗 token |
| **L2 集成层** | 端到端结论是否成立、自洽，含 3 组故障注入 | 无（真实环境） | 消耗 token，需要网络 |
| **L3 数据充分性层** | 必需数据是否确实取得（187 条确定性断言） | 模型完全不参与 | **零 token** |
| **L4 真实世界回验** | **阈值与现实中的实际停航 / 通航是否吻合**（25 条记录） | 模型完全不参与 | **零 token** |

<details>
<summary><b>为何需要分层</b></summary>

<br>

- L1 将工具全部 mock，可以干净地隔离推理能力，代价是**掩盖数据管线的缺陷**：mock 数据总是恰好符合解析逻辑。
  **L3 以零 token 补足这一层**，无需 API Key 即可运行
- 数据管线的错误有「取到 / 未取到」的客观状态，测试可以捕获；**知识库的错误则是静默的**：阈值写错一个数字，
  所有测试依然全部通过，因为期望值本身就是按该阈值标注的。**L4 以真实世界的结果回验阈值**，是唯一能发现阈值本身存在缺口的一层
- **L4 的标签不依赖专家判断**：某日是否实际停航，是官方与媒体已公布的客观事实

</details>

完整设计与断言清单见 [docs/evaluation.md](docs/evaluation.md)。

### 结果

> 评测脚本只输出到终端、不落盘，以下数字均可通过本节末尾的命令复现。
> L1 数字来自 2026-09-01 的一次运行；L4 不调用模型，2026-09-26 重跑结果逐项一致。

**L4：25 条真实停航 / 通航记录回验**（风使用 ERA5 历史再分析数据，浪高使用 Open-Meteo Marine 历史数据，重建当日风浪）

<p align="center"><img src="docs/images/eval-l4.png" alt="L4 结果" width="760"></p>

- **误报率 0%**：10 个正常通航日均未判为 HIGH
- **召回缺口定位出一条尚未建模的判定维度**：9 条漏判中有 7 条与台风相关。承运人依据台风预警提前停运，
  这是独立于风力与浪高的另一类官方信号。该缺口已记录在案，未以无出处的阈值补齐

**L1：四家模型横评**

<p align="center"><img src="docs/images/eval-l1.png" alt="L1 结果" width="760"></p>

裸判准确率从 **56.4% 到 89.7%**，经规则引擎校验后**均为 100%**。判据越细，模型越容易在相邻等级之间偏差一档，
确定性 verifier 的作用也越明显：它使准确率 56% 与 90% 的模型得到同样正确的最终结论。

**缺失数据场景下的弃权表现。** 6 条用例的证据存在缺失：system prompt 明确要求「宁可说不知道，不要猜」，
证据 JSON 中对应字段为 `null`。四家模型合计 24 次弃权机会，**错过 21 次（87.5%），且 21 次均判为 `LOW`**。
deepseek 的全部 4 条错误、kimi 的全部 5 条错误均出自弃权用例，在数据完整的 33 条用例上两者均无错误。
**由于弃权判定不交由模型，这 24 次的最终结论全部正确。**

**复现**

```bash
python -m evals.l3_sufficiency    # 约 2 分钟，零 token，无需 API Key，187 条确定性断言
python -m evals.run_all           # L3 → L2（真实网络与模型，含 3 组故障注入）→ L4（真实记录回验）
```

## 已知边界

以下场景不在能力范围内，或存在已知限制：

- **未建模台风预警**：L4 定位出的主要缺口，已记录，未以无出处的阈值补齐
- **不覆盖内河与湖泊航线**：内河适用另一套官方标准（按风力分档、不含浪高），与海事判据不通用
- **不核实航线是否存在**：只校验两端分别为已收录的港口或机场，不校验两地之间是否有实际航线
- **三条 `PROD` 规则不属于法规**：小船遇海浪蓝色预警、航空平均风 15 m/s、航空雷暴，均已单独标注并附理由
- **两条来源为二手转述**（一条新闻报道、一条厂商手册数值）：已如实标注未取得原文
- **ERA5 为再分析数据而非预报**：L4 验证的是阈值是否合理，而非预报是否足够准确

完整内容见 [docs/limitations.md](docs/limitations.md)。
